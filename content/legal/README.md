# Пользовательское соглашение и политика конфиденциальности

Здесь лежат тексты документов и PDF, которые из них собираются. Приложение
ссылается на документ с экрана профиля и с экрана согласия, а согласие
пользователя привязывается к версии — поэтому документ считается
опубликованным только тогда, когда у него есть версия с загруженным PDF.
Пока версии нет, `GET /v1/app` отдаёт `legalDocuments: []`, и ссылки в
профиле висят неактивными.

## Что здесь есть

| Файл | Что это |
| --- | --- |
| [terms.md](terms.md) | Пользовательское соглашение — исходный текст |
| [privacy.md](privacy.md) | Политика конфиденциальности — исходный текст |
| `terms.pdf`, `privacy.pdf` | То же, собранное для публикации |
| [build-pdf.py](build-pdf.py) | Сборка PDF из Markdown |

> **Тексты — черновики.** Они написаны по тому, что приложение действительно
> делает (геопозиция, аудио, офлайн-кэш, оплата, пуши, удаление аккаунта), но
> опубликовать их как есть нельзя: в них остались `<<подстановки>>` вместо
> реквизитов, и весь текст должен вычитать юрист.

## Как пересобрать PDF

```bash
pip install fpdf2
python content/legal/build-pdf.py
```

Шрифты берутся из мобильного репозитория (`../vitago-rn-app/src/assets/fonts`),
чтобы документ выглядел как приложение, которому принадлежит. Если репозиторий
лежит не рядом — `--fonts <путь>`.

## Как опубликовать

Документы подключены к манифесту Петербурга ([../spb/manifest.json](../spb/manifest.json)):

```json
"legal": [
  { "type": "terms", "file": "../legal/terms.pdf", "requiresReconsent": true },
  { "type": "privacy", "file": "../legal/privacy.pdf", "requiresReconsent": true }
]
```

Публикует их обычный импорт контента:

```bash
npm run content:import -- content/spb/manifest.json
```

Импорт идёт в ту базу, на которую смотрит `DATABASE_URL`, — то есть публикация
на прод делается там же, где и остальной контент.

`publicUrl` не задан намеренно: веб-страницы с этими текстами пока нет, и
приложение открывает сам PDF. Появится страница — добавьте `publicUrl`, и
приложение станет открывать её, а PDF останется той версией, к которой
привязаны согласия.

`requiresReconsent: true` означает, что изменение существенное и у всех
спросят согласие заново; правки опечаток публикуются с `false`. Повторный
импорт того же файла версию не добавляет — хранилище адресуется содержимым,
и неизменённый PDF даёт тот же идентификатор, поэтому уже данные согласия
остаются в силе.
